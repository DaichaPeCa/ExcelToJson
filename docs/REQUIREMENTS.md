# ExcelToJson V1 要件定義

## 1. 文書の位置づけ

本書は、ExcelToJson V1 の製品仕様に関する唯一の正本である。

- 実装は本書の要件を満たさなければならない。
- 本書にない製品仕様を、実装上の都合や一般的な慣習だけで補完してはならない。
- 本書だけでは実装結果が分岐する場合は、その論点を明示して確認する。
- `AGENTS.md` は作業方法と設計上の指針を定める。本書と矛盾する場合は本書を優先する。

## 2. 目的と対象範囲

Excelブックに記述された表形式のデータを、シート間参照による階層構造を持つJSONへ変換するWindows向けコマンドラインツールを作成する。

### 2.1 V1の技術構成

- C# Console Application
- Excel読み取り: ClosedXML
- JSON生成: System.Text.Json
- 入力形式: `.xlsx`
- Self-contained / Single-file publishを想定する
- 配布先で.NET RuntimeやMicrosoft Excelの事前インストールを必要としないことを目標とする

- ターゲットフレームワーク: `net9.0`
- 開発環境: Visual Studio 2022 17.14最新サービス版、または.NET SDK 9.0.3xx以降の9.0系
- 配布RID: `win-x64`
- 対応OS: Windows 10 22H2以降のx64（Windows 11を含む）

配布物はSelf-contained / Single-fileとし、実行先で.NET Runtime、Visual Studio、Microsoft Excelを必要としない。

### 2.2 対象外

- GUI
- Excelアプリケーションの自動操作
- セル値からJSON型を自動推論する `auto` 型
- 本書で定義していないCLIオプション

## 3. コマンドライン仕様

### 3.1 実行形式

入力Excelファイルを1つだけ指定する。

```powershell
ExcelToJson.exe sample.xlsx
```

### 3.2 出力先

入力ファイルと同じディレクトリに、入力ファイルと同じベース名の `.json` を生成する。

```text
C:\data\sample.xlsx
  -> C:\data\sample.json
```

- 同名のJSONが存在する場合は、変換成功時に上書きする。
- 変換が失敗した場合、新しいJSONを残してはならない。
- 既存の同名JSONがある場合、変換が成功する前にその内容を破壊してはならない。

### 3.3 終了コード

- `0`: 成功
- `1`: エラー

成功時は生成したJSONの絶対パスを標準出力へ表示する。エラー時は、原因を利用者が特定できる日本語メッセージを標準エラーへ表示する。想定外の内部例外では概要と例外メッセージだけを表示し、スタックトレースは表示しない。

## 4. Excelブックの構成

ブックは次の種類のシートから構成する。

| シート | 役割 |
|---|---|
| `setting` | ブック全体の変換設定 |
| `root` | 生成するJSONのルートデータ |
| 任意のデータシート | `root` または他のデータシートから参照されるデータ |
| `_` から始まるシート | 作業用・説明用などの変換対象外シート |

`setting` と `root` は必須である。

予約シート名および参照先シート名は、大文字小文字を区別しない。
実際のシート名そのものは前後空白を除去しない。たとえば ` root ` は予約シート `root` ではない。

```text
setting = Setting = SETTING
root    = Root    = ROOT
```

### 4.1 `_` から始まるシート

- JSON変換対象から除外する。
- `object` または `array` の参照先として指定された場合はエラーにする。

例:

```text
_memo
_work
_sample
```

## 5. `setting` シート

### 5.1 書式

`setting` シートはA列とB列によるKey-Value形式とする。

- `A1` は `key`
- `B1` は `value`
- 設定は2行目以降に記述する

例:

| key | value |
|---|---|
| rootType | object |
| emptyCell | omit |
| dateInputFormat | |
| dateOutputFormat | |

設定キーと設定値は前後の空白を除去して解釈する。設定キーおよび列挙形式の設定値は、大文字小文字を区別しない。

同じ設定キーが複数回記述されている場合はエラーにする。重複判定も大文字小文字を区別しない。

- 2行目から最終使用行までを読み、A列とB列がともに空の行は読み飛ばす。
- A列が空でB列だけに値がある行はエラーにする。
- C列以降は説明用途として無視する。
- V1で定義されていない設定キーはエラーにする。
- `key` / `value` ヘッダーは前後空白を除去し、大文字小文字を区別しない。

### 5.2 設定項目

| key | 必須 | 許容値 / 動作 | デフォルト |
|---|---:|---|---|
| `rootType` | 必須 | `object`, `array` | なし |
| `emptyCell` | 任意 | `omit`, `null`, `emptyString` | `omit` |
| `dateInputFormat` | 任意 | 文字列セルを日付として解析する入力形式 | `DateTime.Parse()` 相当 |
| `dateOutputFormat` | 任意 | 日付・日時を文字列化する出力形式 | 8.4節のISO 8601形式 |

#### `rootType=object`

`root` シートのデータ行は、ちょうど1行でなければならない。その1行をJSON objectへ変換する。

#### `rootType=array`

`root` シートの全データ行をJSON arrayへ変換する。

#### `emptyCell=omit`

該当するJSONプロパティ自体を出力しない。

#### `emptyCell=null`

該当するJSONプロパティをJSON `null` として出力する。

#### `emptyCell=emptyString`

該当するJSONプロパティをJSON空文字列 `""` として出力する。

空セルの扱いは、ヘッダーまたはデータセルに指定された型変換より先に適用する。したがって、空セルに対して `number`、`boolean`、`date`、`object`、`array` の変換や参照解決を試みない。ただし、データセルのメモに記述された型名と参照先シート定義の静的な妥当性は検証する。

## 6. データシートの表構造

`root` を含むすべてのデータシートは、同じ基本構造を持つ。

| A | B | C | D |
|---|---|---|---|
| ID | name | profile | items |
| R001 | Alice | P001 | G001 |

### 6.1 ヘッダー行

- 1行目をヘッダー行とする。
- `A1` は `ID` とする。
- B列以降のヘッダーセル値をJSONプロパティ名として使用する。
- JSONプロパティ名の前後の空白は除去する。
- 同一シート内でJSONプロパティ名が重複した場合はエラーにする。
- JSONプロパティ名の重複判定では、大文字小文字を区別する。たとえば `name` と `Name` は別のプロパティ名である。
- A1から最後の非空ヘッダーまでを連続した表範囲とし、途中の空ヘッダーはエラーにする。
- ヘッダーで定義されていない列にデータがある場合はエラーにする。
- A1の `ID` は前後空白を除去し、大文字小文字を区別せずに検証する。
- ID列だけでB列以降がないシートを許可し、そのレコードは空のJSON objectとする。

### 6.2 ID列

- A列はシート内のレコードを識別し、シート間参照を解決するためのID列とする。
- IDはJSONへ出力しない。
- IDは常に文字列として扱う。
- IDの前後の空白は除去する。
- IDでは大文字小文字を区別する。
- `001`、`01`、`1` はそれぞれ別IDとして扱う。
- `USER001` と `user001` は別IDとして扱う。
- IDの重複自体はエラーにしない。参照時に `object` / `array` ごとの件数条件を検証する。
- rootを含むすべての有効なデータ行で、IDは空にできない。
- 文字列型でないIDは、実行環境のカルチャとセル書式を反映したExcel表示文字列へ変換してから前後空白を除去する。
- ID列の型は常に文字列であり、A列のデータセルにあるメモはJSON型指定として解釈しない。

### 6.3 データ行の範囲

- 2行目からデータを読み取る。
- 最初に全セルが空の行が現れた時点で、そのシートのデータを終了する。
- 一部のセルだけが空の行は有効なデータ行である。
- 終了と判定した空行より後ろの行は読み取らない。
- 物理的な空セルと、文字列または数式結果が空文字列のセルを空とする。空白文字だけの文字列は空としない。
- 数式結果が空文字列のセルだけで構成される行も、全セルが空の行として終了する。
- 値が全セル空でメモだけが存在する行も、全セルが空の行として終了する。その行および後続行のメモは型指定として読み取らない。

## 7. JSON型指定と変換

B列以降のヘッダーセルのExcel「メモ」（旧コメント）で、列の既定JSON型を指定する。共同編集用のスレッド型「コメント」は対象外とする。ヘッダーにメモがない場合、またはメモが空か空白だけの場合は `text` とする。

B列以降の有効なデータセルにも同じ書式のメモを記述できる。データセルに有効な型指定がある場合は、そのセルだけヘッダーの既定型を上書きする。データセルにメモがない場合、またはメモが空か空白だけの場合は上書きせず、ヘッダーの既定型を使用する。

型名とメモ中の制御情報は、前後の空白を除去し、大文字小文字を区別せずに解釈する。

V1で使用できる型は次のとおりである。

```text
text
number
boolean
date
object:シート名
array:シート名
```

ヘッダーとデータセルのどちらでも、未知の型、または参照先シート名が空の `object:` / `array:` はエラーにする。エラーには型を指定したセルの位置を含める。

データセルが空でも、メモに記述された型名と参照先シート定義は静的に検証する。ただし、5.2節のとおり空セルの出力動作を先に適用し、値変換、参照件数の検証、参照解決は行わない。

### 7.1 `text`

- JSON stringとして出力する。
- 値から別のJSON型を推論しない。
- 通常のtextデータは前後の空白を除去しない。
- 文字列型でないセルは、実行環境のカルチャとセル書式を反映したExcel表示文字列を使用する。

例:

```text
00123 -> "00123"
" Alice " -> " Alice "
```

### 7.2 `number`

- JSON numberとして出力する。
- Excelの数値セルは、その数値を使用する。
- 文字列セルは、実行環境の `CultureInfo.CurrentCulture` で解析する。
- 内部表現は `decimal` とする。
- 文字列では符号、小数点、桁区切り、指数表記を許可し、通貨記号は許可しない。前後空白は許容する。
- Excelの日付・日時セルをシリアル値としてnumberへ変換することは許可しない。
- decimalの範囲外および非有限値はエラーにする。
- numberへ変換できない場合はエラーにする。

### 7.3 `boolean`

- JSON booleanとして出力する。
- 次の文字列表現を許可する。判定では大文字小文字を区別しない。

| 入力 | 出力 |
|---|---|
| `true` | `true` |
| `false` | `false` |
| `1` | `true` |
| `0` | `false` |
| `yes` | `true` |
| `no` | `false` |

- booleanへ変換できない場合はエラーにする。
- Excelの真偽値セル、および数値セルの `1` / `0` もそれぞれ `true` / `false` として許可する。
- 文字列表現では前後空白を除去しない。

### 7.4 `date`

8章の規則に従い、JSON stringとして出力する。

### 7.5 `object:シート名`

セルの値を参照IDとして、指定シートから一致する1行を解決し、JSON objectとして入れ子にする。詳細は9章に従う。

### 7.6 `array:シート名`

セルの値を参照IDとして、指定シートから一致する全行を解決し、JSON arrayとして入れ子にする。詳細は9章に従う。

## 8. 日付と日時

### 8.1 共通方針

`date` 型は、解析後の値だけでなく、元入力が「日付」か「日時」かという情報を保持して出力まで引き渡す。

時刻の値が `00:00:00` かどうかで日付 / 日時を判定してはならない。

### 8.2 Excelの日付セル

- Excelの日付・日時セルは `DateTime` として扱う。
- 日付 / 日時の判定には、セルの表示形式に時刻要素が含まれるかどうかを使用する。
- 表示形式に時刻要素がなければ日付、あれば日時とする。

### 8.3 文字列セル

- `dateInputFormat` が指定されている場合は、その形式に従って解析する。
- `dateInputFormat` が未指定の場合は、`DateTime.Parse()` 相当の広い解析を行う。
- 入力文字列に時刻部分が存在したかどうかを保持し、日付 / 日時を判定する。
- `dateInputFormat` が指定されている場合、その形式に時刻部分が含まれるかどうかも判定材料にできる。
- 解析できない場合はエラーにする。
- 入力解析には `CultureInfo.CurrentCulture` を使用する。
- 日付成分を持たない時刻だけの文字列はエラーにする。
- `Z` またはUTCオフセットを持つ文字列は実行環境のローカル時刻へ変換し、タイムゾーン情報を除去して保持する。

例:

```text
2026/08/13          -> 日付
2026/08/13 00:00:00 -> 日時
2026/08/13 14:30    -> 日時
```

### 8.4 出力形式

`dateOutputFormat` が指定されている場合は、日付・日時のどちらにもその形式を優先して使用する。
独自出力形式には `CultureInfo.InvariantCulture` を使用する。

未指定の場合は、タイムゾーンを付加しない次のISO 8601形式を使用する。

| 元入力 | 形式 | 例 |
|---|---|---|
| 日付 | `yyyy-MM-dd` | `"2026-08-13"` |
| 日時 | `yyyy-MM-dd'T'HH:mm:ss` | `"2026-08-13T14:30:25"` |

元Excelデータにタイムゾーン情報がないため、デフォルト出力には `Z` や `+09:00` などを付加しない。

## 9. シート間参照

### 9.1 共通規則

- ヘッダーまたはデータセルのメモの書式は `object:シート名` または `array:シート名` とする。
- 型名と参照先シート名の前後の空白は除去する。
- 型名と参照先シート名は大文字小文字を区別しない。
- セル値は参照先シートのIDとして解釈する。
- 参照IDはIDの規則に従い、前後の空白を除去し、大文字小文字を区別する。
- 参照先シートが存在しない場合はエラーにする。
- `_` から始まるシートへの参照はエラーにする。

### 9.2 `object` の件数条件

参照IDと一致する行を指定シートから検索する。

| 一致件数 | 結果 |
|---:|---|
| 0件 | エラー |
| 1件 | その行をJSON objectへ変換 |
| 2件以上 | エラー |

### 9.3 `array` の件数条件

参照IDと一致する行を指定シートから検索する。

| 一致件数 | 結果 |
|---:|---|
| 0件 | エラー |
| 1件以上 | 一致する全行をJSON arrayへ変換 |

### 9.4 多段階ネスト

参照先のデータシートも、さらに別のデータシートを参照できる。変換処理は参照を再帰的に解決する。

```text
root
  -> object:profile
       -> array:addresses
            -> object:country
```

### 9.5 循環参照

自己参照および間接的な循環参照を禁止する。循環参照を検出した場合はエラーにし、JSONを生成しない。

循環は実際に解決中のレコード経路で判定する。同一シートを参照する列やシート依存関係だけではエラーにしない。エラーにはシート、行、IDからなる参照経路を含める。`root` シートを参照先として使用することも許可し、実レコードが循環した場合だけエラーにする。

```text
A -> A
A -> B -> A
```

## 10. 大文字小文字と前後空白

### 10.1 大文字小文字を区別しない制御情報

- `setting` / `root` の予約シート名
- 参照先シート名
- settingのキー
- settingの列挙形式の値
- JSON型名

### 10.2 大文字小文字を区別するデータ

- ID
- 参照ID
- JSONプロパティ名
- 通常のtextデータ

### 10.3 前後の空白を除去するもの

- JSONプロパティ名
- settingのkey / value
- メモの型指定
- `object:` / `array:` の参照先シート名
- ID / 参照ID

### 10.4 前後の空白を除去しないもの

- 通常のtextデータ

## 11. 数式セル

- 数式そのものではなく、数式の計算結果を使用する。
- 取得した計算結果には、通常セルと同じ型変換規則を適用する。
- 計算結果を正常に取得できない場合はエラーにする。
- ClosedXMLによる再計算と、Excelが保存したキャッシュ済み計算結果のどちらを利用するかは実装時に技術検証してよい。ただし、上記の外部仕様を変更してはならない。
- まずClosedXMLによる再計算結果を使用し、再計算できない場合はExcelが保存したキャッシュ済み計算結果へフォールバックする。
- 再計算とキャッシュのどちらからも結果を取得できない場合はエラーにする。
- 数式結果がExcelエラー値の場合は、到達したセルの変換時にエラーにする。

## 12. JSON出力

- 文字コードはBOMなしUTF-8とする。
- インデントありで整形する。
- ID列は出力しない。
- JSONプロパティの値は、型指定、空セル設定、日付設定、参照規則に従う。
- プロパティはExcelの列順、root配列とarray参照の要素はExcelの行順を維持する。
- JSON numberの字面（末尾ゼロや指数表記）は保持せず、decimal値をSystem.Text.Jsonで出力する。

## 13. エラー処理と最低限の検証項目

入力Excelの不正または変換失敗を検出した場合は、JSONを生成せず、原因を表示して、0以外の終了コードで終了する。

少なくとも次をエラーにする。

- コマンドライン引数が仕様を満たさない
- 入力ファイルを読み取れない
- `setting` シートが存在しない
- `root` シートが存在しない
- `setting` の1行目が規定の `key` / `value` ヘッダーではない
- settingキーが重複している
- `rootType` が指定されていない
- `rootType` が `object` / `array` 以外
- `emptyCell` が `omit` / `null` / `emptyString` 以外
- `rootType=object` でrootのデータ行がちょうど1行ではない
- データシートのA列がID列として成立していない
- 同一シート内に重複するJSONプロパティ名が存在する
- ヘッダーまたはデータセルのメモに未知のJSON型が指定されている
- `object:` / `array:` の参照先シート名が空
- 参照先シートが存在しない
- `_` から始まるシートを参照している
- `object` 参照の一致件数が0件または2件以上
- `array` 参照の一致件数が0件
- `number`、`boolean`、`date` のいずれかに変換できない
- 数式結果を取得できない
- 循環参照が存在する

エラー表示には、可能な範囲で問題のシート、セル、設定キー、プロパティ名、参照先など、修正箇所を特定できる文脈を含める。

設定、シート、ヘッダー、型定義など独立して判定できる静的な不正は、一度の実行で可能な範囲まで集約して表示する。値変換や再帰的な参照解決では、安全に判定できない派生処理を継続しない。

rootから到達しない通常データシートも、構造、ID、ヘッダーおよびデータセルの型定義、参照先定義、空行終端を検証する。値変換、参照件数、循環はrootから到達したレコードだけを検証する。ただし、空行終端の判定に必要な数式結果を取得できない場合は、未参照シートでもエラーにする。

## 14. 変換例

### 14.1 `setting`

| key | value |
|---|---|
| rootType | object |
| emptyCell | omit |
| dateInputFormat | |
| dateOutputFormat | |

### 14.2 `root`

| ID | name | profile | items |
|---|---|---|---|
| R001 | Alice | P001 | G001 |

ヘッダーのメモ:

```text
name    -> 指定なし（text）
profile -> object:profile
items   -> array:items
```

### 14.3 `profile`

| ID | age | birthday |
|---|---|---|
| P001 | 30 | 1996/05/10 |

ヘッダーのメモ:

```text
age      -> number
birthday -> date
```

### 14.4 `items`

| ID | name | quantity |
|---|---|---|
| G001 | Apple | 2 |
| G001 | Orange | 3 |

ヘッダーのメモ:


## 15. 受け入れ条件

V1は、少なくとも次を自動テストで確認できたときに受け入れ可能とする。
